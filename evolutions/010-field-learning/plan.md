# Field learning — EVOLVE Medium

## Outcome and authorization

Strengthen the existing learning loop so recurring findings change the builder's next plan and prevention checks. The owner authorized implementation and deployment after requesting a review of real project experience. The later clarification prioritizes serious defects reaching repeated audits, while retaining broader lessons about roadmap drift and verification. No audit-round cap.

## Scope

- Extend the existing audit ledger with optional learning records; preserve legacy entries.
- Add a read-only checker and synthetic boundary tests. Connect it to the existing ledger checker and AUDIT/EVOLVE entry/closure.
- Document pre-handoff scope discovery, repair regression checks, stable consequence-based triage, evidence retention and finish-before-start in one execution guide; existing rules point there.
- Run local checks, fresh correctness/privacy review, then publish through a checked PR. No product runtime or parallel-owned implementation changes.

## Existing patterns and tradeoffs

Extend Rules 30–32, audit-ledger-check and lens-retro rather than adding a lens or automatic rule writer. Existing pattern: E3 reference scan is not required. Machine checks validate records and evidence presence; they cannot establish semantic prevention. Fresh review and executed counterexamples remain necessary. Missing historical inputs stay unassessed; no fabricated backfill or measured-improvement claim.

## Verification

Synthetic tests: empty/malformed records, duplicate incidents/rounds, open recurring class, false closure, missing evidence, traversal and links, self-review, unknown adoption, class filtering and current Material. A clean control must pass. Verify legacy-ledger compatibility and new ledger-check invocation; run Bob coherence, rule tags and document checks. Fresh reviewer checks privacy, behavior and integration. Reconciliation records actual results and deferred limits.
