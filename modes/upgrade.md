# MODE: UPGRADE — Step Sequence (D-019)
<!-- living doc -->

> Moved word for word from `build-protocol-core.md` on 2026-10-29 (D-032), so the file every session reads holds only the step line and a pointer.

Brings a project Bob set up earlier up to date with the current Bob. Run from the **project** folder. The script only reads until the user approves; it never touches a file outside the set Bob installs (hooks, their `.claude/settings.json` entries, the reviewer, the daily dropped-work check, the lists Bob creates once, the Bob pointer in CLAUDE.md) plus its own `.bob/` folder.

U1: **Report** — `node "$(realpath ~/.claude/skills/bob/..)/scripts/bob-upgrade.mjs"` (changes nothing). Retell it in plain English: for each item, what it does for the user, **why Bob changed it** (the D-number and one line from `decision-log.md`), and what applying it would change. Groups: Bob has a newer version · missing (new in Bob) · **the project has its own version** (a same-job tool of its own, found by name in its hook settings or script folders — left alone; list it in `.bob/differences.md` if deliberate, D-020) · **waiting for your test command** (the green gate is never switched on while its test command is Bob's placeholder, D-020) · **damaged** (a required-checks list the merge guard can't read — offered as a named reset, D-020) · **a hand step** (a file the project fills in itself, so the report says what to change and nothing applies it: the Works and Evidence columns of an older Capability Traceability Matrix, and the wiring check `templates/wired.test.mjs` — missing, or older than Bob's apart from its CONFIG and UNWIRED blocks; D-036) · changed here on purpose (`.bob/differences.md` — left alone) · changed here, reason not written down. → U2: **Decide** `→ HG` — all safe updates, some, or none; for every "changed here, reason not written down": keep it (add one line with the reason to `.bob/differences.md`) or take Bob's. → U3: **Apply** — `--apply all` or `--apply <item>,<item>`. Every replaced file is copied to `.bob/backups/<date>/` first. A hook that can stop work arrives **warn-only** (it says what it would have blocked and blocks nothing); the merge guard has no warn-only mode (D-018) and starts in its "no CI yet" stage instead. Commit the result like any change. → U4: **Switch on** — after the user has seen the warn-only hooks behave, `--enforce <item>`. The commit-time document check (`commit-sweep`) stays warn-only in an existing project until its documents pass, then `--apply commit-sweep` makes it block. → U5: **Backwash** — ask "does this project do something better than Bob?" for each line in `.bob/differences.md` and anything else the project invented. If yes: write it in general terms (no project names, numbers or internals — Bob is public), add a decision-log entry in Bob, change Bob, then run UPGRADE here again and delete the line from `.bob/differences.md`.

**Install record.** `bob-init` writes `.bob/installed.json` (what Bob installed, from which Bob commit) and an empty `.bob/differences.md`. A project with no record still works: each file is compared with Bob's current version and every past version in Bob's history. Bob's current version of each piece is whatever `bob-init` writes today — the upgrade script runs it in a throw-away folder, so `bob-init` stays the one source.

**Learning adoption (D-038, manual, no historical rewrite).** After the install report, run the preflight in `reference/field-learning.md` against the existing audit ledger. Missing learning records mean unassessed. With the owner's selected upgrade scope, preserve all entries and add only source-backed incident records; run plan/close checks and prove the consuming workflow runs its prevention tests. Do not replace a populated ledger with a template or infer adoption from an install version. The updated AUDIT/EVOLVE method reads this guide directly from Bob.
