# M11-dispatcher

See LANES.md for who builds this folder, and the build rows for what (0b-6: R-0b-55 to 65, 67, 68).

Every outside effect (launching, stopping, typing into a session, git, alerts) is a port that the wiring connects, so the tests run on fakes, throwaway folders and throwaway git repositories only. No file here starts a Claude session; `only-send-safe.test.mjs` checks that no file types into a session except through a `send` port wired to M4's send-safe guard.

## The tick's ports

`tick()` takes every outside effect as a port, so the wiring module (written at the live proof) is the only place that touches the Mac. `main.mjs` reads a config file `{ wiring, lockFile }` (both absolute paths), imports the wiring module and calls its `wire(config, { limitedSync })`, which returns `{ rec, rules, ports }`. The ports:

| Port | Used by | What it does |
|---|---|---|
| `alert(text)` | the one sender, `sendAlerts` (`alerts.mjs`), at the start of each pass (alongside the safety steps) and at its end | One plain-text message to Joe. No step calls it: each step gets the outbox instead (L47). It must start its send and return a promise at once (an `async` function): the first send calls it in the tick's first moment, so a port that does its work before returning would hold up the stops (audit 0b-6 r7 M1) |
| `board()`, `healthy()`, `resume()` | outage | The running sessions with their liveness; whether network, sign-in and usage are fine; whether Joe said resume |
| `outboxSessions()`, `wait(ms)`, `startReadonly(x)`, `replyToLead(x)`, `intakeFs` | intake | The sessions and their outbox folders; the settle wait; a Lead's read-only start; a note back to the Lead; optional file-reading overrides for tests |
| `leads()` | leads | Per Lead: `{ lead, size, outboxNames, questionOpen, send, stopSession, startLead }` |
| `sessions()`, `probe`, `launch`, `stopGroup`, `saveWork`, `hostLock`, `pauseLead` | pass | As in `pass.mjs` |
| `hasSession`, `gateAlive` | limits | As in `merges.mjs` |
| `hasReviewer`, `requestReview`, `reviewAlerts` | limits | From `reviewPorts({ requests, status, reviewUid, mainHead })` (`review-requests.mjs`, L65, L66): the review runner's `requests/` folder, its `status.json`, the review user's uid, and `mainHead(installed)` → `{ commit, since }` for the stamp check (main's commit, 40 hex, and when main first moved past the installed commit); without `mainHead` there is no stamp check |
| `filesOf` | undo | The files a merged PR changed |
| `sendFrontDoor`, `restartFrontDoor`, `startMinibase`, `frontDoorAlive`, `strayFrontDoor`, `frontDoorHandoff` | phone | As in `phone-link.mjs` |
| `cleanup: { copiesRoot, sealRoot, mirrorFor, git, saveWork }` | cleanup | As in `cleanup.mjs` |

With two Claude accounts (R-1-89), every port that starts, lists, checks or stops a session goes through `accountPorts` in `account-ports.mjs`; see "Two Claude accounts" below for the contract.

Facts the tick writes: `signed-in-account` is read (missing or stale: nothing starts), `step-error-<step>` (one alert per distinct error, cleared on success), `last-full-pass` (when every step last ran and how each ended).
