| Files the scan cannot read are refused (LEAD-CALLS L28; audit R-0b-47 round 2 MAT-A, round 3 MAT-1, MIN-1) | Deliberate rule, fails safe | Every new or changed file must be plain UTF-8 text, or the push is refused: a zip, a .tgz, a renamed archive, a locked file, UTF-16 text, a program. A text file holding a packed file written out as base64 (gzip, zip, 7z, bzip2, xz, zstd) is refused too. A product's rules entry may allow PNG images under named paths, `product.allowed_binaries`, for example `[{ path: 'docs/**/*.png', type: 'png' }]`. PNG is the only type offered, because it is the only one read in full: its real type is read from its bytes (a zip renamed to .png is refused), its chunks must come from a fixed list of plain kinds (no private or packed chunks but the image data), nothing may follow its end, and its image data must unpack, as one stream, to exactly the size its header states. The unpacked image data is scanned as well. JPEG, GIF, WebP and fonts are refused until each can be read as fully; an entry naming them allows nothing. A worker that deliberately encodes data some other way can still hide it in text; the scan stops accidents and the named tricks. No entry means no binaries, which is the default for the docs and research lane at the first cutover. | The lead, per product entry. | When a product needs images. |
