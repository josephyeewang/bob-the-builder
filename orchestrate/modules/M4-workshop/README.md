# M4-workshop

## Open items (written down so they are not lost)

| Item | Kind | What could go wrong | Who decides or checks | When |
|---|---|---|---|---|
| A question asked in plain text (audit R-0b-29 m11) | Decision for the lead | If a role asks the person something in ordinary text and ends its turn, without the question box, the session looks idle and a WRAP nudge may be typed over the question. | The lead: either every role question must use the question box (a rule in its role file), or the Dispatcher checks the last message for an open question before any WRAP. | Before the Dispatcher's WRAP nudge is turned on (0b-6). |
| A stop while a helper's dialog is still open (audit R-0b-29 m12) | Live check, next to L1 | A turn's end counts as proof that any dialog was answered. If a background helper's permission dialog can still be on screen after the main turn ends, a nudge could be typed into it. | The person and the builder, on the pinned Claude Code. | With live check L1, and again at every version pin change. |
| Two question boxes open at once (audit R-0b-29 round 2) | Live check, next to L1 | The code remembers every open box on the stored session record, so a restart of the tracker does not forget one; the check only confirms whether two boxes can happen. | The person and the builder. | With live check L1. |
| The launch label is not yet passed in (audit R-0b-29 round 3 n1) | Wiring, for the row that builds the hook relay; three decisions owed | The tracker can now ignore hooks from a stopped launch, but nothing yet gives each launch a label, passes it to the hooks or calls `beginLaunch`. Until then every session accepts every hook, as before. Three places differ from upstream and need a decision: (1) a hook that names a launch is accepted by a record that has none (upstream drops it); (2) a hook that loses its launch label leaves the session "startup pending" for good; (3) `beginLaunch` keeps an exited session marked as exited. | The builder of the hook relay (the launcher's start step calls `beginLaunch`; each hook line carries the label). | Before the Lead or Front Door restart path (§5.5) is turned on. |
| Two permission dialogs on screen at once (audit R-0b-29 round 4 n4) | Live check, next to L1 | The tracker remembers one open dialog (as upstream does). If two can be on screen at once (for example from parallel helpers) and the later one is answered first, the session can look idle while the first dialog still shows, and a nudge could be typed into it. The code assumes one dialog at a time. | The person and the builder, on the pinned Claude Code. If two can show at once, keep a list of open dialogs. | With live check L1. |
| A question box closed without an answer (audit R-0b-29 round 2 n7) | Live check, next to L1 | If the person presses Esc on a question box or types `/clear`, no answer hook fires, so the session stays "waiting on a question" until the person types. Safe (nothing is typed), but the session waits. | The person and the builder. | With live check L1. |
| "Only the guard types" is a convention (audit R-0b-29 round 2 n2) | Known limit | The guard's store, messenger, lease and start gate are reachable from outside, and `personGuard` is exported next to `sendSafe`. Nothing in the language stops another file typing without the guard. A static test would. | The Dispatcher's builder (0b-6): add a test that no other file calls the messenger directly. | With the Dispatcher. |
| The guard's test tables are thinner than upstream's (audit R-0b-29 round 2 n4) | Known limit | Upstream tests more state combinations per guard line. Every safety line here has its own test, and mutations of them are caught, but the tables are smaller. | The builder, when the guard next changes. | At the next guard change. |
| One-shot runs inside a worker's folder (audit R-0b-29 round 3 n4) | Wiring, for the row that builds the hook relay | A one-shot `claude -p` run (the baseline and smoke runs, or the read-back) fires hooks too. If its hooks were counted as the worker's, its prompt would look like the person answering and could lift a dialog. | The builder of the hook relay: drop hooks from non-interactive runs by the run's entry point, as upstream does (upstream #6454). Do not filter by session id: Claude gives a session a new id after `/clear`, so every later hook would be dropped and the session would never be typed into again. | With the hook relay. |
| Every setting name is unconfirmed (audit R-0b-44 M-1) | Live check L2, the person and the builder | Claude Code silently ignores a setting name it does not know, so a misspelt name would leave the lock-down looking on but off. The launcher now refuses any name in the role file or the start flags that is not in the confirmed list (`CONFIRMED` in `launcher/settings-names.mjs`) for the exact pinned version. The list is empty today, so **every launch refuses until L2 runs**. | The builder runs L2 on the pinned version: for each name, show it took effect (in the start message, or by a test that fails when it is off) and add one line to the list with how it was shown and the version. | Before the first real launch, and again at every version pin change (the list then counts for nothing until re-proven). |
| A hook that crashes during a session (audit R-0b-44 M-1) | Live check, next to L2 | Launch check 7 shows each hook blocks when it fails at launch. Whether the pinned Claude Code also blocks the call when a hook crashes later, mid-session, is not shown by any test here. | The person and the builder, on the pinned Claude Code: break one hook script mid-session and confirm the next call is blocked. | With L2, and at every version pin change. |
| Edits and writes in the worker's mode (audit R-0b-44 round 1, minor) | Live check, next to L2 | The worker runs in "don't ask" mode with allow rules for exact test and build commands only. Whether that mode lets it edit and write files inside its own copy without an allow rule is not shown. If not, the worker cannot do its job (safe, but stuck). Adding allow rules would also need launch check 5 to accept them. | The builder, on the pinned Claude Code. | With L2. |
| A search over a folder that holds a secret file (audit R-0b-44 round 1, minor) | Known limit | The secret-file hook checks the paths a call names. A search (Grep) run over a whole folder can still read a secret file inside it; the deny-read rules in the role file and the lock-down are what stop it. | The builder, when the hook next changes. | At the next hook change. |
| The compaction hooks are not test-run at launch (audit R-0b-44 round 1, minor) | Known limit | Launch check 7 test-runs the five safety hooks. The two hooks that save and restore context around compaction are installed but not run at launch, so a broken one shows only when compaction happens. | The builder. | With the row that builds compaction handling. |

The launch check (audit m3): the tracker's half is built (`ActivityTracker.beginLaunch`, tested); the wiring is the open item above.
