# wiring/: the modules a config names

The login job's config names a wiring module by its path, and the entry script imports it. This folder holds the
Dispatcher's and the robot job's (R-0b-162). The review runner's wiring is in `modules/M4-workshop/launcher/review-wiring.mjs`.

| File | What it is |
|---|---|
| `dispatcher-wiring.mjs` | `wire(config, { limitedSync })` for `modules/M11-dispatcher/main.mjs`. It returns the real Record (M9), the real rules (the M10 reader, engine and `shared/rules.mjs`, with a read-only GitHub client) and the tick's ports. The config keys are listed at the top of the file. |
| `owner-ports.mjs` | Part C's interface (L741): the ports the Dispatcher reaches through the owner-side worker runner (sessions, probe, board, outboxSessions, stopSession, launch, stopGroup, saveWork, pauseLead, and cleanup's copiesRoot and saveWork); probe, stopGroup and saveWork take any session and the wiring routes each by kind to the runner that started it. For each: what goes in, what comes out, how a failure is answered (a sync port throws when the runner's status file is stale or unreadable; an async port answers `{ ok: false, reason }` only when the outcome is known, except where noted, and leaves an unknown one to the tick's time limit), where the launch doc ends and the session record (the one source for branch, outbox and attempt, L744) begins. Its stub refuses each port. `worker-ports.mjs` wires the sync ports (sessions, probe, board, outboxSessions, stopSession) to the worker runner's status and requests folder, with the review runner's reviewers and auditors merged into sessions (PR B, L925, L927); it still lists launch, stopGroup, saveWork and pauseLead as not wired. The stop step does not reach review or audit sessions yet: one of a cancelled card runs until it ends on its own, and its verdict is thrown away when taken (L933). A change of shape needs a lead ruling. |
| `owner-status.mjs` | Part C, runner step 1 (L747): the Dispatcher's read of the worker runner's status file (owned by the owner's user, plain, written by no one else, the runner's shape, under 3 minutes old; anything else throws) and the runner's share of the five sync ports built on it. stopSession is true only for a used-up launch request with nothing running under the id; otherwise it writes one stop request and answers false. Not wired yet: owner-ports.mjs still refuses. |
| `owner-asks.mjs` | Part C, runner step 2 (L759): the four async owner ports (launch, stopGroup, saveWork, pauseLead). Each writes one request file and waits for the runner's answer in its status, trusting it only when the rest of that status agrees; it never answers ok: false while the outcome is unknown, and stops at its own limit (past every tick limit) with the tick's timedOut answer. Not wired yet. |
| `runner-launch.mjs` | Part C, runner step 2 (L757, L759): the runner's launch wall. It renders each session's settings with the runner's own folders and refuses the launch ("not walled") unless #320's checkRunnerWall passes on them; the script role, with no design profile yet, is refused. |
| `runner-files.mjs` | Part C, runner step 2 (L763, #320 m2): the runner writes its status as a new file renamed over the old one (a hard link planted to the old one never gets the next status), and reads a request only when it is a plain file with one name, owned by the orchestrate user, and small. |
| `worker-runner.mjs` | Part C, runner step 3: one pass of the worker runner. It reads the Dispatcher's requests, acts on each once, checks its sessions, and writes its status, keeping its memory before every write. Every outside effect is a port. |
| `runner-loop.mjs` | Part C, runner step 4: the loop around one pass (a tick every 4 s, the memory file read at start and after a failed tick) and the process-group ports (groupGone, stopGroup), which tell the runner's own group from a reused number by the leader's start time. |
| `runner-ports.mjs` | Part C, runner step 5: the real start (the card's claim checked, the copy, the outbox, the walled settings, M4's launch() and claude as its own group's leader), saveWork (M4 save-work), outboxDrained, size and pauseLead. What other lanes still owe (the worker checks, the prompt, the lock-down runner, the Lead's wrap-up) is a port that refuses until it is given. |
| `runner-main.mjs` | Part C, runner step 5: `node runner-main.mjs <config>`, the runner's LaunchAgent entry: the config through the shared job-config reader, one lock for the runner's life, the loop until SIGTERM. |
| `runner-job.mjs` | Part C, runner step 5: the runner's LaunchAgent file, built by M11's loginJobPlist with the owner's HOME and Umask 077 (needs #292's loginJobPlist). Setup places it on the Mini; it is never loaded on a laptop. |
| `worker-ports.mjs`, `review-ports.mjs`, `phone-ports.mjs` | The tick's ports, by who wires them. Each lists the ports it doesn't answer yet and returns the ones it does; `wire()` adds them. To wire a port, change its file and take it off that list. `dispatcher-wiring.mjs` doesn't change. Each port has one home: `wire` takes `groups` (these three by default) and stops the start on a port on two lists, answered by two files, both answered and listed, neither answered nor listed, one the tick doesn't read (`TICK_PORTS`), or a file answering `alert` or `approvals`. The cleanup group follows the same rules (`cleanupProblem`). |
| `not-wired.mjs` | The refusal a port gives until it is wired. |
| `private-folder.mjs` | `privateFolder`, the one check for a private folder (the approvals state folder, the robot key folder, the seal folder). `dispatcher-wiring.mjs` re-exports it. |
| `dispatcher-wiring.test.mjs` | Runs `node main.mjs <config>` as a separate process with this wiring. It checks one full pass, a second run, rules Joe has not approved, an unknown config key, and that every port not wired yet refuses. It runs in CI. |
| `robot-main.mjs` | The robot job's entry (L236, L238): `node robot-main.mjs <config>`. One round of the robot passes (gate, heartbeat, caught-up, watch, then deliver), each with its own time limit, under a lock of its own. A pass that fails is told to Joe once a day; the other passes still run. Exit 0 ran, 1 not started, 2 late. |
| `robot-wiring.mjs` | `wire(config)` for `robot-main.mjs`. The Dispatcher's config keys, less `approvalsStateDir` and the five review keys (`REVIEW_CONFIG_KEYS`), plus `keyDir` and `dispatcherLockFile`. It refuses to start unless the job runs as the Record's owner and owns `keyDir`, a private plain folder (L238). Real now: caught-up, and the heartbeat's "the Dispatcher is late" check. Gate, the rest of the heartbeat, and watch refuse until their clients exist. |
| `robot-wiring.test.mjs` | Runs `node robot-main.mjs <config>` as a separate process: every pass is told or runs, the startup refusals, caught-up pushing once on the Dispatcher's return (never mid-outage), and the late-Dispatcher alert. It runs in CI. |
| `fake-github.test-helper.mjs` | The test's only stand-in, for api.github.com. It can be loaded into a whole process with `node --import`. |

**Not wired yet (PR A of R-0b-162).** Every port other than the Record, the rules, the lock, approvals and the review ports below throws `not wired yet: <port>` when called. The step that needs that port fails, and the owner is told which step and why. Nothing answers with a made-up value. PRs C and D wire these ports. **Approvals (L270)** is wired: each tick it runs M2's schedule pass for the product, so a product whose rules file says `onboarding.state: active` is turned on. Its state folder is `<approvalsStateDir>/<product>`, one per product so two products never share a told-once mark; at start-up the folder and the product's subfolder are made if missing, and the start is refused unless each is a plain folder of this user's, private and writable (L295). Its GitHub writes and transcript copies still refuse (`not wired yet: approvals.gh` / `approvals.copies`) until a GitHub identity that can write exists, and there is no phone push. An ask that needs them is not failed: M2 alerts that ask's cause once (per ask and cause, kept in the state folder), then again each day while the ask still waits (L309), and at once after a push for it went through and a new failure came. A product name is lower case letters, digits and `-`, a letter or digit first (setup's rule, shared/product-paths.mjs PRODUCT, #378 r1 m3), and products.json refuses two names that differ only in case, since they would share one folder on a Mac (L309).

**The review ports (A1, A2) are wired.** `review-ports.mjs` answers `mainSha` and `planView` through the rules reader's read-only GitHub client, so they can't write, and `requestReview`, `hasReviewer` and `reviewAlerts` through the review runner's requests folder and status file (the five review keys at the top of `dispatcher-wiring.mjs`). The review user must be neither the Dispatcher's own user nor `ownerUid`, or the start stops (L674). Whether the runner's copy is behind main is judged from root's record beside that copy; a record older than 25 minutes (two of root's updater turns plus its fetch limit) keeps the hold and says the updater may have stopped. `gateAlive` still refuses.

**Part C's first ports are wired (L739).** Five config keys hold them, all at the top of `dispatcher-wiring.mjs`: `reviewRoot`, `mirror`, `sealRoot`, `hostLockPath` and `hostLockUid`.
- Cleanup's `mirrorFor` gives the product's mirror. The mirror is checked when the Dispatcher starts and again on each use: it must be a plain folder, the Dispatcher's own, and not writable by others, and pass safe-git's mirror check (the template config; no grafts, shallow, commit-graph, alternates or hooks). A card of another product gets null.
- Cleanup's `git` is safe-git on that mirror only, runs only `ls-tree` and `merge-base`, checks the mirror on each call, and is held to at most 60 s.
- Cleanup's `sealRoot` is made private when the Dispatcher starts. It is checked again on every read, so a folder that can't be used fails the step rather than skipping the sweep.
- `filesOf` reads a commit's changed files from the mirror through `limitedSync`, after safe-git's repository check. An empty answer or a failed read throws.
- `hostLock` answers Joe's host.lock text. It reads the file only when the opened file belongs to `hostLockUid` (the owner's Mac user; never root, the Dispatcher's own user or the review user), so a link or a swap in the owner's folder can't put another user's file in the Record. It answers null only when the file is missing from a folder that exists. Anything it can't read throws, and the pass reads that as "not known".
- `reviewEnded` is M9 `runnerEnded` on `<reviewRoot>/ended`. A runner folder that is gone, is a link or is not the review user's is a refusal, never "not ended".
- `cleanup.copiesRoot` and `cleanup.saveWork` still refuse.

**No channel to Joe is connected yet.** M13's `makeAlerts` (GitHub issues) is the channel; lane 3 is building its delivery adapter (L235), and this folder wires it in once it exists. Until then the alert port writes each alert to the login job's log and answers "not delivered", so alerts stay in the record's unsent queue and are never marked as told.

**Alerts reach Joe with the Dispatcher dead (L242).** The alert queue belongs to the Record, and delivery runs in the robot job, never in the Dispatcher (L236, L237). The robot job's last pass, `deliver`, sends what the passes before it queued, in the same round. Its port is lane 3's M13 `deliverAlertsPass`; until that lands, `deliver` refuses and the alerts stay queued.

**When the worker-exit port is wired (PR C):** it must call M12 `writeLimitHit` with its own default clock, never the pass's frozen `now`, and a test must pin that (audit #125 r1 m-2). A hit stamped with the pass's start time could be dated before the card's run began, and then it would never resume the card.
